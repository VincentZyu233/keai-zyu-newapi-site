## ⚡ 核心机制：GOAT Plan 的 "10x Possible" 到底是什么噱头？

> [!NOTE] 官方白皮书与 10x 营销真相
> **"Most of a coding agent's volume is cache reads. We run our infrastructure at leading ~95-98% cache hit rates."**  
> Command Code 官方最初打出 8x 宣传，近期更进一步升级为 **"10x Possible"**（宣称支付 $10 可享受高达 $100 配额）。  
> 详见官方说明文档：👉 [How is 10x possible? (commandcode.ai)](https://commandcode.ai/docs/plans/goat#how-is-10x-possible)

```
              ┌──────────────────────────────────────────────┐
              │  Coding Agent 真实请求结构 (如 Codex 100K 上下文)  │
              └──────────────────────┬───────────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
 【95% 历史代码与项目上下文 (Cache Read)】              【5% 本轮新增编辑指令 (New Input)】
 • T0/T1 合作模型：官方专有集群，享 95%+ 缓存折扣      • 按极低增量费率结算
 • 成本几乎降为零，所以 $10 经久耐用！               
```

### 为什么说 8x/10x 是营销噱头？
1. **理论极值 vs 真实扣费**：
   所谓的 "10x Possible" 完全是基于 **超长历史上下文 95%~98% 都是缓存命中** 计算出的数学极限理论值。只有在深度共建集群（DeepSeek、智谱 GLM、通义千问等）上，缓存读取单价降到几分钱，才能实现相当于 1 折（1.25 折）的耐用度。
2. **离开了缓存加速，噱头秒破灭**：
   一旦请求没有命中缓存，或者使用了未经官方专有集群加速的模型（如闭源大厂 Gemini、Grok、Mistral），每一次几万至十万 Token 的长上下文都要按标准原价全额计费！单次交互的消耗就相当于国模几十次交互，短短几轮对话就能将 5 小时的滑动窗口额度彻底烧光！
3. **真实中转站倍率设置**：
   在 New-API 网关数据库底层，所有模型的 `ModelRatio` 与 `GroupRatio` 统一设为 `1.0` 基准。文档中所标称的输入/输出费率是基于上游官方标杆基准价与实付 1.25 折折算的参考价格。

## 💡 最佳实践建议

1. **写代码日常主力**：一律认准 **`deepseek/deepseek-v4.1-flash`** 或 **`zai-org/GLM-5.2`**。不仅速度飞快、逻辑扎实，且配额消耗几乎可以忽略不计。
2. **深度推理与架构设计**：选用 **`deepseek/deepseek-v4-pro`**（满血思考链）。
3. **多模态与超长长文**：选用 **`Qwen/Qwen3.8-Max`** 或 **`zai-org/GLM-5.3`**。
